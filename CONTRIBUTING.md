# Contributing to MPS Model & System Descriptors

Thank you for helping build PhysioVerse.

## You do not need to write code

Most contributions to this project are scientific, technical, data-curation, standards, protocol, validation, or community contributions.

## Fastest way to contribute

1. Open **Issues**.
2. Click **New issue**.
3. Choose **Make a community contribution**, **Nominate a public resource**, or **Review a working draft**.
4. Complete what you know and submit.

## What makes a strong contribution

- Be specific.
- Include a DOI, accession, publication, repository, protocol, standard, ontology, or other public source when available.
- Explain the MPS context and why the contribution matters.
- Separate evidence from suggestions.
- Do not upload confidential, proprietary, patient-identifiable, or otherwise restricted information.

## More involved contributions

If you want to edit a working document directly, open an issue first or submit a pull request with a focused change. Keep each pull request limited to one clear contribution.

## Questions

If you are unsure where your contribution belongs, open a community contribution issue and describe what you have. A maintainer can help route it.

## Submit, Review, and Incorporate a Contribution

Use your own GitHub account. You can submit public evidence or a suggestion through this project's **[contribution form](https://github.com/PhysioVerse-OSE/mps-model-system-descriptors/issues/new?template=community-contribution.yml)**, or propose a focused documentation change through a pull request. Proposed changes can be submitted from a fork.

**For a resource or scientific proposal:** provide the source, intended context, contribution, and any uncertainty. Separate reported evidence from your recommendation. Use Not reported or Unknown rather than infer missing details.

**For a pull request:** edit one relevant document or add one source-supported record, summarize what changed, and link the related Issue and references. Check the diff before submitting. The [browser-based contribution guide](https://github.com/PhysioVerse-OSE/PhysioVerse-OSE/blob/main/START_CONTRIBUTING.md#two-ways-to-contribute) explains the fork, edit, and pull-request route without local Git commands.

A maintainer reviews submissions and may ask for clarification or revision. Accepted material can be incorporated into the relevant project resource with source links and contribution history. Standards-oriented materials remain working drafts unless an applicable formal process establishes a different status.

Keep supporting information and revisions in the relevant GitHub thread so the review remains traceable.

For attribution details, see [Credit for your contribution](https://github.com/PhysioVerse-OSE/PhysioVerse-OSE/blob/main/START_CONTRIBUTING.md#credit-for-your-contribution). Issue and Discussion participation is valuable even when it does not appear in GitHub's commit-based contributor graph.
